1. Introduction

1.1 Purpose

The GAIT GraphQL API Interaction Tool facilitates seamless interaction with GraphQL APIs by allowing users to construct, execute, and optimize queries efficiently. It integrates Natural Language Processing (NLP) to interpret user input in natural language and convert it into structured GraphQL requests.

1.2 Document Conventions

This document follows IEEE 830-1998 standard conventions for Software Requirements Specification (SRS). The following typographical conventions are used:

  • Bold for section titles and key terms.
  • Monospace for code snippets and API endpoints.
  • Italics for emphasis.

1.3 Intended Audience and Reading Suggestions

This document is intended for:

  • Developers: To understand system architecture, API endpoints, and coding conventions.
  • Project Managers: To track requirements and development progress.
  • Researchers: To explore how NLP can be used in GraphQL query generation.
  • Testers: To verify compliance with specifications and performance requirements.

2. Overall Description

2.1 Product Perspective

GAIT is an independent system that interacts with external GraphQL APIs. It consists of three main modules:

  • Frontend (React.js): Captures user queries and displays results.
  • Backend (Flask): Orchestrates query execution and manages API requests.
  • NLP Module: Converts natural language input into structured GraphQL queries.

2.2 Product Functions

The system provides:

  • GraphQL Query Generation: NLP-based conversion from natural language to GraphQL.
  • Schema Exploration: Introspection query execution.
  • Frontend Interface: User-friendly interaction and query execution.
  • Speech-to-Text Conversion: Audio-based query support.

3. External Interface Requirements

3.1 User Interfaces

Frontend: React.js-based interactive UI.

3.2 Software Interfaces

Flask REST API, SQLite Database, and OpenAI API for NLP query generation.

4. System Features

4.1 GraphQL Query Generation

Description: Converts natural language input into GraphQL queries.

Priority: High

  • System must validate user input.
  • System must generate syntactically correct GraphQL queries.
  • System should provide suggestions for incorrect inputs.

4.2 Backend Module

4.2.1 Architecture

  • Flask API: Handles incoming HTTP requests, routes them to the appropriate modules, and returns processed responses.
  • Chatbot Module: Parses user input, extracts intent, and dynamically generates GraphQL queries based on the stored schema.
  • NLP Module: Uses OpenAI models to process user messages and convert natural language queries into structured GraphQL queries.
  • Database Module: Utilizes SQLite for persisting GraphQL API links and schemas, allowing efficient retrieval and updates.
  • Speech-to-Text Module: Converts audio files to text using SpeechRecognition and pydub, enabling voice-based query execution.

4.2.2 Flask API Endpoints

  • /chat (POST): Receives user messages, processes them via the chatbot, and returns GraphQL queries or responses.
  • /speech-to-text (POST): Accepts audio files, converts them into text, and returns the transcribed query for further processing.

4.2.3 Chatbot Module

Upon receiving a user query, the chatbot first checks for GraphQL links and schemas in the database. If no schema is found, it prompts the user for a GraphQL API link. If a schema is present, it utilizes NLP or rule-based methods to generate a GraphQL query.

4.2.4 NLP Module

The NLP Module employs OpenAI's GPT-based models to process natural language queries. It enhances query accuracy by leveraging schema context, recognizing entity references, and dynamically adjusting query structures.

4.2.5 Database Module

Uses SQLite to store GraphQL API links and schemas. When the server restarts, it clears outdated data and maintains a fresh state for new queries.

CREATE TABLE IF NOT EXISTS graphql_links (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    link TEXT UNIQUE NOT NULL,
    schema TEXT NOT NULL
);

4.2.6 Speech-to-Text Module

Processes audio files submitted by users, converting them to text via Google's speech recognition API. The transcribed text is then processed similarly to standard text queries.

4.2.7 External Integrations

GAIT integrates with OpenAI for NLP-driven query processing, utilizing Flask for backend orchestration. It communicates with external GraphQL APIs via introspection queries and dynamically constructs GraphQL requests based on user input.

5. Nonfunctional Requirements

5.1 Performance Requirements

  • Response Time: The system is designed to process and respond to user queries within 5 seconds under standard operational conditions.
  • Scalability: The architecture supports concurrent handling of multiple user requests without performance degradation, ensuring consistent response times.

5.2 Safety Requirements

  • Data Integrity: The system ensures that all data transactions are accurate and consistent, preventing data corruption during processing and storage.
  • Error Handling: Robust error detection and handling mechanisms are implemented to maintain system stability and provide informative feedback to users.

5.3 Security Requirements

  • Data Protection: Sensitive information, including API keys and user data, is encrypted both in transit and at rest, adhering to industry-standard security protocols.
  • Input Validation: All user inputs are rigorously validated and sanitized to prevent security vulnerabilities such as injection attacks.

5.4 Software Quality Attributes

  • Modularity: The system's architecture is modular, with distinct components for the frontend, backend, and NLP functionalities, facilitating ease of maintenance and scalability.
  • Reliability: The system is engineered to provide consistent and dependable services, with redundancy and failover mechanisms in place to minimize downtime.
  • Usability: The user interface is designed to be intuitive and user-friendly, ensuring that users can navigate and utilize the system's features with minimal learning curve.
  • Maintainability: Codebases for each module adhere to clean coding practices and are well-documented, enabling efficient updates and troubleshooting.

5.5 Business Rules

  • Licensing Compliance: The system and its components comply with all relevant software licenses, ensuring legal usage of third-party libraries and tools.
  • Usage Monitoring: The system includes logging and monitoring features to track usage patterns, aiding in performance tuning and future enhancements.
  • Resource Management: Efficient management of computational resources is prioritized to optimize operational costs, especially when deploying in cloud environments.

6. Other Requirements

  • Internationalization: Future support for multiple languages.
  • Extensibility: Support for additional NLP models.

7. Future Directions

  • Additional GraphQL API authentication methods
  • Advanced NLP model integration

8. Conclusion

GAIT enhances GraphQL query interaction using NLP, making APIs more accessible. Future updates will focus on improving NLP accuracy and expanding API support.
